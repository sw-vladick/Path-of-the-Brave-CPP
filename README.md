# Path of the Brave — 2D Action-Platformer (C++ / SFML / SQLite)

**Path of the Brave** — це мій перший комплексний 2D ігровий проєкт, написаний з нуля мовою C++ з використанням мультимедійної бібліотеки **SFML** та вбудованої реляційної бази даних **SQLite3**. 

Проєкт створювався на початку мого вивчення C++ для практичного опанування об'єктно-орієнтованого програмування (ООП), роботи з ігровим циклом (Game Loop), фізикою, керуванням ресурсами та збереженням стану програми в реляційній БД.

---

## Основний функціонал

* **Бойова система та фізика:**
  * Плавний рух персонажа (біг, спринт, стрибки з гравітацією), ближній бій зі зброєю, механіка відкидання (knockback) та таймери невразливості (i-frames) після отримання шкоди.
  * Балістична фізика польоту снарядів: вороги-вікінги розраховують параболічну траєкторію польоту сокири залежно від дистанції до гравця.
* **Різноманітні типи ворогів та хвилі спавну:**
  * 4 типи ворогів (`Zombie`, `Orc`, `Mini`, `Wiking`) з унікальними характеристиками (HP, швидкість, шкода) та покадровою анімацією станів (біг, атака, отримання шкоди, смерть із плавним зникненням).
* **Інвентар та система Drag-and-Drop:**
  * Повноцінний інвентар та панель швидкого доступу (HotBar) на 4 слоти.
  * Перетягування предметів мишкою (Drag-and-Drop) між інвентарем та хотбаром.
  * Система магазину між рівнями з можливістю прокачки зброї та броні за зібрані монети.
* **Збереження прогресу в SQLite (`DatabaseManager`):**
  * Підтримка 3 слотів збереження з відображенням рівня та точного часу запису.
  * Збереження стану гравця (HP, координати, рівень, монети), всього інвентарю з рівнями прокачки предметів, налаштувань гучності/клавіш, а також стану об'єктів світу (відкриті скрині, вбиті вороги, активовані хвилі).

## Архітектура проєкту

* `sam.cpp` — точка входу, головний ігровий цикл, обробка подій, логіка переходів між рівнями та магазином.
* `Player.h / .cpp` — логіка гравця, фізика, машина станів анімації (`IDLE`, `RUN`, `JUMP`, `FRUN`), відображення HUD та інвентарю.
* `Enemy.h / .cpp` — логіка поведінки ворогів, патрулювання, переслідування гравця та розрахунок атак.
* `HotBar.h / .cpp` — UI-компонент панелі швидкого доступу.
* `DatabaseManager.h / .cpp` — обгортка над `sqlite3` для виконання DDL/DML запитів (створення таблиць, збереження та завантаження стану гри).
* `ResourceManager.h` — централізоване завантаження та зберігання текстур (`sf::Texture`), звукових буферів (`sf::SoundBuffer`) та шрифтів.
* `Menu.h / .cpp`, `Chest.h / .cpp`, `Item.h / .cpp`, `Config.h` — допоміжні класи ігрового інтерфейсу, об'єктів світу та глобальних констант.

## Чому я навчився та архітектурні висновки (Lessons Learned)

Оскільки цей проєкт був моєю першою масштабною роботою на C++, зараз, маючи значно більше досвіду у програмуванні та безпеці, я бачу в ньому низку архітектурних недоліків. Я свідомо залишив основну структуру цього коду як відправну точку у своєму портфоліо, зробивши з нього наступні інженерні висновки:

1. **Принцип єдиної відповідальності (Single Responsibility Principle — SOLID):**
   * *Як реалізовано тут:* Клас `Player` одночасно відповідає за фізику руху, анімацію спрайтів, зберігання інвентарю та рендеринг UI-сітки. Головний файл `sam.cpp` містить занадто багато логіки станів гри (меню, магазин, бій).
   * *Як я пишу зараз:* Розділяю бізнес-логіку, дані та відображення (UI) на окремі незалежні класи, а для керування екранами використовую патерн **State Machine** (`MenuState`, `GameState`, `ShopState`).
2. **Поліморфізм та принцип Open-Closed (OCP) замість розгалужень `if-else`:**
   * *Як реалізовано тут:* У класі `Enemy` поведінка та параметри різних монстрів визначаються через перевірки рядків `if (enemyType == "Zombie") ... else if (enemyType == "wiking")`.
   * *Як я пишу зараз:* Використовую базовий абстрактний клас `Enemy` з віртуальними методами (або компонентний підхід ECS) чи завантаження конфігурацій сутностей із JSON-файлів, щоб додавання нового ворога не вимагало зміни коду існуючого класу.
3. **Принцип DRY (Don't Repeat Yourself):**
   * *Як реалізовано тут:* У `ResourceManager` завантаження текстур і налаштування гучності звуків прописано вручну для кожного файлу, а в `Enemy` та `Player` дублюється логіка гравітації.
   * *Як я пишу зараз:* Виношу повторювану логіку в окремі методи або цикли конфігурації.
4. **Безпека бази даних (Захист від SQL-ін'єкцій та транзакції):**
   * *Як реалізовано тут:* У `DatabaseManager` запити `INSERT` та `SELECT` формуються через конкатенацію рядків (`std::string`), а інвентар зберігається окремими `sqlite3_exec` у циклі.
   * *Як я пишу зараз:* Завжди використовую параметризовані запити (**Prepared Statements** через `sqlite3_bind_int` / `sqlite3_bind_text`) для унеможливлення SQL-ін'єкцій та обгортаю масові вставки в єдину транзакцію (`BEGIN TRANSACTION ... COMMIT`) для швидкодії.

## Керування в грі

* **A / D** — Рух вліво / вправо
* **Shift (утримання)** — Спринт
* **Space** — Стрибок
* **ЛКМ (Ліва кнопка миші)** — Атака мечем / Відкриття скрині / Взаємодія з UI та перетягування предметів
* **1, 2, 3, 4** — Вибір активного слота в HotBar
* **I** — Відкрити / закрити інвентар
* **H** *(можна змінити в налаштуваннях)* — Випити зілля здоров'я
* **F5** — Швидке збереження гри в поточний слот
* **Esc** — Пауза / Назад у меню

## Як зібрати та запустити

1. Клонуйте репозиторій:
   ```bash
   git clone https://github.com/sw-vladick/Path-of-the-Brave-CPP.git
   ```
2. Відкрийте проєкт у Visual Studio 2022.

3. Переконайтеся, що у налаштуваннях проєкту підключено бібліотеку SFML 2.6.x (sfml-graphics, sfml-window, sfml-system, sfml-audio) та файл sqlite3.

4. Скомпілюйте та запустіть проєкт у конфігурації x64.
